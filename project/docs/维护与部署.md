# 维护与部署

评论功能涉及 PHP、MySQL 和匿名 Cookie，部署与数据查看步骤见 [评论系统部署与查看](评论系统部署与查看.md)。

## 日常只需要管理的目录

```text
src/content/notes/
```

增加一篇笔记时，把文章目录复制到这里。推荐结构：

```text
src/content/notes/分类/笔记名称/
├── index.md
└── images/
```

笔记之间使用 `[[笔记名称]]` 建立关系。构建脚本会自动生成图谱数据和文章页面，不需要修改任何 JavaScript 函数。

也可以直接把 Obsidian 的文件夹拖进来：多篇 `.md` 平铺、图片统一放在 `assets` 子目录的布局同样支持，`![[图片名]]` 按文件名自动匹配，共享素材只复制一份。不想发布的笔记在开头加 `draft: true`。

代码块使用标准围栏并写明语言，例如 `python`、`bash`、`powershell`、`cpp`、`javascript` 或 `yaml`。语法高亮由 `highlight.js` 自动完成。

## 配色与字体

七种主题的颜色变量位于：

```text
src/styles/global.css
```

文章排版、代码块和语法高亮颜色位于：

```text
src/styles/markdown.css
```

网站使用的 Ubuntu Mono 文件位于：

```text
public/fonts/UbuntuMono-variable.ttf
```

主题按钮会将选择保存在浏览器本地。修改颜色时只需调整 CSS 变量，不需要修改 Markdown 渲染函数。

## 本地预览

在 `D:\my_project\website\project` 打开 PowerShell：

```powershell
npm run dev
```

访问 `http://127.0.0.1:4321`。新增或删除笔记后，先按 `Ctrl+C` 停止服务器，再重新运行 `npm run dev`。

## 发布

日常发布用仓库根目录的一键脚本（在 Git Bash 中执行）：

```bash
./deploy.sh              # 测试 → 构建 → 备份数据库 → 上传线上 → 推送两个 git 仓库
./deploy.sh "修了某篇笔记"  # 同上，并把说明写进提交信息
```

脚本要求：v2ray 开启「允许局域网连接」（git 推送走 `127.0.0.1:10808`，可改脚本顶部 `PROXY`），`~/.ssh/config` 里有 `blueee-server` 别名。数据库会在每次部署前自动备份到服务器 `/www/backup/database/`，保留最近 10 份。

如果只想手动发布一次：`npm test && npm run build`，将 `dist` 目录里面的内容上传到服务器的宝塔站点根目录（保留服务器上的 `.user.ini`）。服务器只需要构建产物，不需要安装 Node.js，也不需要上传 `node_modules`。

## 仓库分工

- `blueee-server`（公开，即本仓库）：网站全部源码，供大家 contribute / 提 PR。
- `blueee-server-pri`（私有）：数据库密码、nginx 配置等服务器机密与恢复手册，本地在 `D:\my_project\server-ops`。
- `blueee-website`（私有，归档）：旧历史备份，只读。

## 一般不需要修改的文件

- `scripts/prepare-content.mjs`：读取 Markdown、转换双链、复制图片、生成图谱。
- `src/components/KnowledgeGraph.astro`：绘制、拖拽和点击图谱节点。
- `src/components/NavigationSidebar.astro`：笔记目录和收起状态。
- `src/components/ThemeSwitcher.astro`：主题切换与浏览器本地记忆。
- `src/pages/notes/[...slug].astro`：生成笔记页面。
- `src/generated/notes.json`：自动生成，禁止手动编辑。
- `public/generated/`：自动生成，禁止手动编辑。
- `dist/`：每次构建重新生成，禁止在里面长期手改。
